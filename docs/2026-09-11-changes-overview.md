## 功能与入口

页面入口位于左侧导航，使用原应用的中央内容区，保留侧栏和所选会话；“返回对话”恢复原会话。

| 功能 | 入口或操作 | 使用范围 |
| --- | --- | --- |
| 运行服务 | 左侧“运行服务” | 普通账号管理自己的服务，管理员管理所有账号的服务 |
| 文件夹管理 | 左侧“文件夹管理” | 当前账号的专属目录；保留上传、下载、新建、删除、复制与移动 |
| 拖拽移动 | 将条目拖到目标文件夹或“返回上级” | 文件和文件夹均支持；目标同名时拒绝覆盖 |
| Git 克隆与拉取 | 文件夹管理中的“代码仓库” | 需同时开启“允许上传文件”和“允许 git 下载” |

文件夹管理不使用外层弹框，服务列表和文件夹管理均不新开浏览器标签页。拖拽拒绝把目录放进自身或子目录；“移动/粘贴”按钮仍可用于触屏和键盘操作。详细行为见[文件管理说明](plans/2026-09-11-managed-files-page.md)。

## Git 用户名和密码怎么用

公开仓库可将两项凭据全部留空。私有仓库需同时填写用户名和密码／Token；GitHub 的密码栏使用有仓库读取权限的个人访问令牌（PAT）。

1. 在“文件夹管理”进入准备存放代码的目录，点击“克隆仓库”。
2. 填写仓库的 HTTP/HTTPS 最终地址，可指定目标文件夹；留空则使用仓库名。
3. 私有仓库填写“Git 用户名”和“密码／Token”，点击“开始克隆”。
4. 克隆成功后进入该仓库目录。需要更新时重新填写凭据，再点击“拉取更新”。

密码框采用掩码显示。独立凭据在提交、取消或切换目录时清空，只供当次操作使用，不保存在仓库地址或凭据存储中；后续私有仓库拉取不会自动复用。当前不提供“记住密码”。

服务器将凭据限定到当次仓库的有效地址，禁用宿主凭据助手和交互提示；新克隆写入无凭据的 origin。新克隆也能拆出旧式地址中的用户名和密码，但不会批量迁移既有仓库配置中的历史凭据。返回日志及审计对本次凭据做脱敏。

| 情况 | 处理方式 |
| --- | --- |
| 只填写用户名或只填写密码 | 同时填写两项，或全部留空访问公开仓库 |
| 认证失败 | 重新输入凭据，核对仓库读取权限；PAT 还需有效且获得仓库访问授权 |
| 地址发生重定向 | 改为仓库最终地址；携带认证的请求不跟随重定向 |
| 使用 SSH 地址或 URL 查询参数 | 此入口仅接受无查询参数的 HTTP/HTTPS 地址 |
| 拉取无法快进合并 | 先处理本地修改或分叉历史；页面只执行 `git pull --ff-only` |

## 持续运行与账号权限

Agent 在个人服务器工作区使用 `dev_server` 启动测试环境，服务由 systemd 托管。会话结束、工具命令结束或 Harness 重启不停止服务；已启用的服务在进程退出后自动重启，并在服务器启动后恢复。用户要求停止，或管理员主动停止后，会取消自动重启和开机启动。

| 身份与入口 | 可以查看或停止的范围 |
| --- | --- |
| 普通账号的 Agent：`dev_server` | 当前账号、当前项目 |
| 普通账号的“运行服务”页面 | 当前账号所有项目的托管服务 |
| 管理员的 Agent：`dev_server_admin` | 所有账号的托管服务 |
| 管理员的“运行服务”页面 | 所有账号的托管服务 |

页面支持搜索、状态筛选，并显示项目、端口及重启次数；手动停止前确认目标账号和服务。页面管理范围限已登记的测试服务，不是系统全部进程。跨账号权限由服务端复核，停止操作记录审计。

应用监听地址、允许的 Host、网络防火墙和端口映射仍决定外部能否访问；持久托管不能代替这些配置，也不能保证故障应用始终可用。详细运行和部署约束见[持久测试服务说明](plans/2026-09-11-persistent-development-services.md)。

## 导出与记忆整理

Session 导出支持可信子代理沿持久化父会话继承读取权限，并校验每级归属、禁用状态及异常关系；普通 fork 不继承此授权。原失败会话已验收导出成功，ZIP 中的 5 个 JSONL 文件通过完整性检查；其他普通账号的导出请求被拒绝。

Mnemon 的自动整理修复了工具执行对象与结束回执的关联，整理提交后可以正常结束。自动整理按活动阈值筛选长期事实和项目结论，不会把每一条聊天原文都写进记忆库。临时安装、测试或没有长期价值的对话可以得到 `skipped`，这本身不是故障。

本轮真实会话验收中，自动整理触发一次、失败数为 0，结果为 `skipped`；该验收明确要求不保存临时测试信息。会话日志仍保存完整过程，不能把记忆条目数量当成对话是否持久化的判断依据。
