Development dependencies use the published `0.1.7-rc.2` packages so TypeScript resolves the current public plugin APIs. The package does not impose a runtime DSH dependency: DSH owns the profile and loads this package through its plugin link. Runtime startup is fail-closed for the supported `0.1.2`, `0.1.3`, `0.1.5`, `0.1.6`, and `0.1.7` minor lines: each must pass the settings host-mode and authenticated Cookie-bridge checks; unknown or malformed identities are rejected before patching or public listeners.

## Plugin surfaces

| Surface | Status | Requirement |
|---|---|---|
| HTTP UI/API plugins | Code-level compatible | The gateway removes only its own authentication cookie and preserves plugin cookies; local regression and test-server lifecycle/provider flows cover the official UI/API path and generic third-party boundary. |
| Plugin combo URLs | Regression-tested | `/plugins/??...` query bytes, including the second `?`, remain unchanged; covered by the version-agnostic regression suite. |
| Plugin business `token` query | Regression-tested | Only the alpha index launch-token context strips bare `token`; plugin paths retain it. |
| Third-party endpoint (HTTP or WebSocket) | Conditional | Write the path into `MCP_GATEWAY_SSH_ENDPOINTS` (one variable for both transports and both capabilities; a rule is `[owner:][ws:|http:]path`). Writing the path is the registration; no handshake or approval flow exists. Subusers then reach it by having the owner tick their SSH-endpoint and official-terminal toggle — both keys are required, neither alone grants third-party access. The alpha.2 official terminal does not need registration and uses the same toggle; its known HTTP/mux methods are explicitly handled by the gateway. `pluginManager`, `agentTeams`, and `officeToPdf` remain hard-denied for subusers even when a broad rule matches them. `terminal` stays outside the generic official namespace classification so a broad registration cannot bypass the toggle. With `DSH_PASSWORDS_ENV_FILE` set, valid `.env` changes are polled every 5 seconds without a restart; otherwise restart the gateway after editing `.env`. |
| Unregistered third-party paths | Not supported | `/api/*` namespaces outside the official set and non-official root-level plugin routes are fail-closed for subusers (a rejection line is logged). Fine-grained adapters for known plugins live in `plugin-compat.ts` behind `MCP_GATEWAY_PLUGIN_COMPAT` (default off). The gateway core ships no plugin-specific paths or auto-detection. |
| Unknown WebSocket paths | Not supported | Rejected by default for subusers; the owner remains unrestricted. |
| Alpha Remote mux, subuser `workspace/follow` and `session/control` | Code-level compatible | Gateway applies resource filters; local frame tests and test-server lifecycle/multiuser concurrency probes validate the baseline flows. |
| Alpha.1 `workspaceFiles/changes` | Subuser path-scoped | HTTP unary is fail-closed. Remote subscriptions require an authorized session scope and an in-workspace target; `ready/change` frames are validated and out-of-scope absolute paths are dropped without closing the carrier. |
| Alpha Remote mux, subuser `session/follow` and `$events` | Regression-tested | `session/follow` accepts ordinary and subagent addresses; parent access is required, child grants are not; `$events` retains current correlation filtering |
| Alpha.2 official terminal | Owner/admin pass-through; subuser controlled by SSH permission | Owner/admin terminal HTTP unary methods (`environment`, `shells`, `list`, `create`, `write`, `resize`, `rename`, `close`) and Remote mux (`terminal/follow`, `terminal/retain`) are forwarded without SSH endpoint configuration. For subusers, the same `allowSsh` permission used for registered third-party SSH controls the official terminal: when off, `list/environment/shells/close` return fixed local UX stubs, other terminal RPCs return 403, and mux terminal streams return a per-stream `terminal/unavailable` error; when on, the official terminal HTTP and mux methods are forwarded. `terminal` remains outside `OFFICIAL_API_NAMESPACES` and is handled by this explicit gateway branch, so broad third-party registration cannot bypass the SSH permission. |
| Official `job` / `account` RPCs | Subuser-compatible with scoped limits | `job/list` and `job/follow` are Remote streams bound to an authorized session; only jobs whose owner matches that session are returned, and `job/kill` is session-scoped. `account/getState`, `getProfile`, `getBalance`, and `account/watch` retain the official read-only host account view under the selected function-first policy. Unknown/future unary account methods and `startSignIn`, `cancelSignIn`, and `signOut` are denied for subusers. |
| rc.2 `schedule` RPCs | Subuser-compatible with session scope | `list`, `history`, `update`, and `delete` require an authorized session ID. The global `catalog` response is filtered to authorized sessions for subusers; owners receive it unchanged. |
| Workspace ordering | Subuser-compatible with scoped limits | `workspace/insertBefore` waits for the filtered workspace/session baseline when needed; `insertSessionBefore` requires an authorized session in the requested workspace. Success responses are scoped to that same workspace and filter IDs to the caller's visible resources. Ordering is the host DSH registry's global order (not a per-user private order), so an authorized subuser can affect the shared order just as the owner can. |
| Dynamic Cordis runner | Subusers fail-closed | The complete `dynamicCordisRunner` namespace is blocked for subusers, including `runHostHalf`, runner inventory/control methods, known diagnostic methods, namespace roots, and unknown/future methods. This prevents a session-scoped request from reaching host-side dynamic package execution; owner/admin behavior is unchanged. |
| Directory picker | Native in the 0.1.7 line | The pinned rc.2 package tree ships the official `dsh-host-directory-picker*` / `dsh-client-ui-directory-picker-*` packages; dsh-passwords does not insert duplicate official picker loaders. Owner/subuser directory permission and workspace cleanup flows are covered locally and by the test-server lifecycle E2E. |
| Connection Cookie bridge | Test-server verified | `patch status` shows `patched` or `native`; the gateway refuses startup when the bridge is unavailable. The 2.7.5 test-server deployment with rc.2 reports `patched`. |

## Lifecycle contract

For the pinned DSH `0.1.7` line target (currently `0.1.7-rc.2`) and the supported DSH `0.1.2`, `0.1.3`, `0.1.5`, and `0.1.6` boundaries, gateway startup is fail-closed: the settings host-mode patch and authenticated Cookie bridge must both be present. Missing settings exits with code `35`; a missing or unsupported bridge exits with code `33`; an invalid or unknown DSH minor exits with code `37` before patching. Codes `1`, `30`, `31`, `32`, `33`, `34`, `35`, `36`, and `37` are permanent startup failures and are not retried by the host plugin. The version gate covers stable `0.1.7` and SemVer prereleases such as alpha, beta, next, rc, and build metadata, while rejecting `0.1.8`; local CLI tests cover supported variants and rejection paths.

Run `dsh-passwords uninstall` before removing the package directory or running `npm uninstall`. It removes only the `dsh-passwords` link and bundle item from the selected web profile, then rolls back only matching hash-protected patches. It leaves `.env`, `data/`, databases, certificates, and unrelated plugins unchanged. If profile dependency reconciliation or patch rollback fails, it restores the original `package.json`, `pnpm-lock.yaml`, and `node_modules` materialized state. The no-DSH case uses stable exit code `34`, independent of `LANG`; the pinned rc.2 patch and failure paths are covered by local CLI tests, and the released alpha.2 (v2.7.4) test-server patch/health checks passed. Browser rendering remains a manual acceptance boundary.
